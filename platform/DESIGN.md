# rs-face Platform UI · 设计哲学

> 目标:让"上传 → 看结果"变成 3 步、30 秒。所有 UI 决策都回到同一个问题:
> **这件事用户要做几次?有没有省一次?**

---

## 一、为什么现在要重设计

旧版平台堆叠了 7 个独立的"功能岛",问题不是多了,而是**它们互相绑架**:

| 旧组件 | 一句话问题 | 用户实际花费 |
|---|---|---|
| 顶栏 5 个图标 | 谁都想要"露出",结果什么都看不到 | 需要扫一眼找到「新 建」 |
| 4 个 KPI 卡 + 4 个侧栏 tab | 8 个数字讲同一件事 | 切 tab 选状态、记数 |
| 独立 Inspector 抽屉 | "仪表板"藏在按钮后面 | 多一次点击 |
| 3 个 dropzone (image / video / stream) | 用户本不在意类型 | 多一步选 tab |
| Lightbox 弹窗 | 2 个图标按钮只多展示一次原图 | 多一次点开/关闭 |
| Help 弹窗 | 8 个快捷键写给"老手" | 新人直接关掉 |
| Batch 操作条 | "导出/删除 N 个任务",使用率 < 5% | 占用顶部一整行 |

**核心矛盾**:每个组件单独看都有用,合在一起看像控制室仪表板,新人打开会先问"我该点哪里"。

## 二、设计原则(每一项都能写到代码里)

### 原则 1 · 单主路径 · Single Primary Path
用户最常做的事只有一件:**看一眼自己刚上传的任务进展**。
所以主区 **永远只有一个状态**,三个里选一个,中间态设计为自动过渡:
1. **空** — 给动作(放文件/粘贴 URL)
2. **进行中** — 给反馈(进度 + 实时帧 + 数字变化)
3. **完成/失败** — 给结果(原图、检出人脸、导出按钮)

副操作(主题切换、搜索)只在顶栏,绝不进主区争夺视线。

### 原则 2 · 一个动作 · 一处入口 · One Action, One Place
- 删除:只在右键菜单 / 详情头部 ⋯ 菜单里有,**不在任务卡上**(怕误删)
- 重新跑:错误 banner 一行就有,**不在工具栏**(把"补救"贴在"失败"旁边)
- 主题:就顶栏一个按钮,**不放侧栏**(设过就行,不需要专门入口)
- 算法选择:跟任务一起出现(上传时),**不放设置页**(用户不会回去找)

### 原则 3 · 时间预算显式化 · Budget Visible
每个常做动作,数一数它点几次:

| 动作 | 旧版 | 新版 | 节省 |
|---|---|---|---|
| 上传一张图 → 看到结果 | 4 步(`+ 新建` → 选图 → 选算法 → 关 modal) | **1 步**(拖进画布) | -75% |
| 查看最近一条任务的耗时 | 3 步(进详情 → 切 tab → 翻图表) | **1 步**(主区脚注一行) | -67% |
| 删除已完成任务 | 2 步(`选中 → 批量 → 删除`) | **1 步**(右键 → 删除) | -50% |
| 暂停长视频 | 3 步(进详情 → 拉滑块 → 切 tab) | **1 步**(主区空格键) | -67% |
| 切换深浅色 | 1 步(顶栏按钮) | 1 步 + **自动记忆** | + 持久化 |

### 原则 4 · 减法优先 · Subtraction First
每个新加的元素,先问:
1. 它替代了哪个旧元素?(不能替代就不加)
2. 它 7 天内用户会用几次?(<3 次就放抽屉/菜单里,不要放主区)
3. 占不占屏幕高度?(任何"占用一整行"的元素必须能折叠)

## 三、布局决策(每个决策都能映射到 CSS/HTML)

```
┌─────────────────────────────────────────────────────────────┐
│  ◐ rs-face          [搜索]                  ◐ 主题           │  ← 顶栏 48px,single row,no icon cluster
├──────────┬──────────────────────────────────────────────────┤
│          │                                                  │
│ 进行 2   │                                                  │
│ ┌──────┐ │          ┌────────────────────────────┐          │
│ │ #382  │ │          │                            │          │
│ │ 1:24  │ │          │                            │          │
│ └──────┘ │          │     主 画 布(原图 / 视频 /    │          │
│ ┌──────┐ │          │     进度 / 拖放区 · 三态)   │          │
│ │ #381  │ │          │                            │          │
│ │ done  │ │          │                            │          │
│ └──────┘ │          └────────────────────────────┘          │
│          │                                                  │
│ 今天 47  │      ┌─ 帧轨 ━━━━●━━━━━ ──┐   ← 256 x 4px 最小化  │
│ ...      │      └─────────────────┘                          │
│          │                                                  │
│ 较早 18  │      8 张脸 · 0.42s/帧 · 1.3 GB · CUDA·gpu0       │  ← 一行式统计,no cards
│ ...      │                                                  │
├──────────┴──────────────────────────────────────────────────┤
│ ⌨n 上传 · j/k 切换 · ⌫ 删除 · ? 帮助 · 共 67 任务 · 2 运行 │  ← 状态条,一文字行
└─────────────────────────────────────────────────────────────┘
```

### 3.1 顶栏 · 3 个元素
- **`◐ rs-face`** — 品牌 + 路由回根的入口(点击回到主画布空状态)
- **`[搜索]`** — 唯一"导航级"工具,支持任务 id、文件名
- **`◐ 主题`** — auto / dark / light 三态循环,按钮文案本身就是当前态

**删除**:`+ 新建`、`☰ 抽屉`、`? 帮助`、`🍔`、`📌`。原因:这些都让用户多一次决定"先点哪个"。

### 3.2 侧栏 · 1 列 · 3 段
不是 4 个 tab,而是 **按时间分**(系统帮你组织,不需要用户分类):
- **进行**(≤ 8 个,运行中/排队/失败置顶)
- **今天**(过去 24h 的完成项)
- **较早**(其余,自动折叠,显示数量)

**为什么不放"已完成 / 错误" tab?**
因为在主页里看到 status dot 就够了。Tab 是 UI 的"目录",不是数据本身。

### 3.3 主画布 · 三态单例
永远只有这三态之一在显示:
1. **`empty-state`** — 全屏居中,**最大字号**的一行字"拖入或粘贴 URL",下面 4 行提示(支持哪些格式、最大多少、示例、当前 GPU 状态)
2. **`working`** — 大块媒体 + 顶部一行进度(已处理 / 总数 · ETA) + 底部一行统计(命中脸 / 命中率 / 平均耗时 / 后端设备名)
3. **`done`** — 同 `working` 但去掉进度条,在右下显示"结果 / 原图"切换

**为什么不做成 4 个 tab(原版)?**
因为 tab 把状态切成 4 屏,但用户从来不想"我现在要看统计"——他们只想"看任务现在怎么样了"。所以这三个数字/动作 **永远跟着原图出现**,不藏在二级页。

### 3.4 状态条 · 1 行
最底一行 13px 的小字,只说"平台现在怎么样了":任务总数 / 正在跑 / 快捷键提示。永远不抢焦点。

## 四、保留的高级能力(给老用户的"曲径通幽")

我们不删除任何能力,**只是把"高频"留在表面,"低频"移到二级**:

| 能力 | 旧版位置 | 新版位置 |
|---|---|---|
| 批量删除/导出 | 侧栏底 bar | 任务卡右键菜单 |
| 切换算法 | modal 里的下拉框 | 上传前一行 chip,**只在上传态出现** |
| 切到原图 | 按钮 | 数字键 `1` |
| 查看每帧结果 | timeline 单独区域 | 视频用空格暂停 + 1-9 直跳 |
| 算法仪表板 | Inspector 抽屉 | 详情 ⋯ → "统计" 子菜单 |
| 多任务对比 | 单独 Compare 模块 | 选中 2 个任务右键 → "对比" |
| 活体标定数据 | Liveness 表 | 详情 ⋯ → "统计" |
| 时间线 24h 图 | Inspector 一块 | 详情 ⋯ → "统计" |

**为什么不直接删?**
老用户已经养成肌肉记忆,我们尊重它,只是把它"塞进抽屉"。新人不会撞上。

## 五、可量化的目标(部署后看)

- 顶栏可点元素:5 → **2**(降低发现成本 60%)
- 主区最高同时可见的交互控件:14 → **3**(任务卡 + 主画布 + 状态条)
- 首屏加载 CSS:3 文件 / 2376 行 → **1 文件 / 600 行**
- 首屏可见的"具体数字"(KPI 等):26+ → **4**(运行 / 脸总数 / 命中 / 后端)
- 从"打开到看到第一张检测图"的平均时间:< 5 秒(含上传)

## 六、你会如何在新的 UI 上操作

### 第一次上传一张图
1. 打开 `http://localhost:20080/`
2. 主画布中央写着"拖入图片/视频 或粘贴 URL"——直接拖一张图
3. (可选)选择算法 chip:**默认 / 对称 / CNN / 亮度** —— 大多数人就用默认
4. 主画布变成进度条:1.2s/帧 · 检出 8 张脸 · 后端 `cuda:0`
5. 看到结果,按 `1` 切到原图对比,`Shift+S` 导出 JSON,`⌫` 删除

### 批量处理 20 个视频
1. 选中左上角"上传"chip
2. 一次拖入 20 个视频 —— 自动 1 个任务 = 1 个视频
3. 侧栏**进行**段逐渐填满,可点任意一项查看实时进度
4. 全部完成后,选中今天那段 → 右键 → "导出全部 JSON" → 一份 zip

### 删除昨天的工作
1. 滚到侧栏**较早**段
2. `⌘ 多选` 几个任务
3. 右键 → "删除选中"(3 个)

## 七、未来如果还要加,先问这三个问题

1. **它在主页出现吗?** 不能,则不放主页
2. **它 7 天内用户点 3 次以上吗?** 不能,则放 ⋯ 菜单
3. **它会让首屏可见控件数 > 3 吗?** 是,则继续折叠

— 任何让用户**多一次决定**的 UI 都是负债。
